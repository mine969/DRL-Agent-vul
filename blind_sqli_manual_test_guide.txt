📋 WHAT IS BLIND SQL INJECTION?
--------------------------------------------------------------------------------
Unlike regular SQL injection where you see database errors, Blind SQLi works by:
- Sending TRUE/FALSE conditions in SQL
- Observing DIFFERENCES in the server's response
- No error messages needed - just behavior changes

================================================================================
🎯 STEP-BY-STEP TESTING INSTRUCTIONS
================================================================================

STEP 1: Test with TRUE condition (1=1)
--------------------------------------------------------------------------------
URL to visit in your browser:
https://levelup.melivecode.com/search?q=' AND 1=1--

What this does:
- The ' closes the original SQL query
- AND 1=1 adds a condition that is ALWAYS TRUE
- -- comments out the rest of the query

Expected result: Page should load NORMALLY (shows search results or normal page)


STEP 2: Test with FALSE condition (1=2)
--------------------------------------------------------------------------------
URL to visit in your browser:
https://levelup.melivecode.com/search?q=' AND 1=2--

What this does:
- Same as above, but 1=2 is ALWAYS FALSE
- This should make the SQL query return NO results

Expected result: Page should be DIFFERENT (empty results, different content)


STEP 3: Compare the results
--------------------------------------------------------------------------------
If the website is vulnerable:
✅ TRUE condition (1=1) → Shows results/normal page
✅ FALSE condition (1=2) → Shows empty/different page
✅ DIFFERENT behavior = VULNERABLE!

If the website is NOT vulnerable:
❌ Both URLs show the same page
❌ Both show errors or blocked
❌ WAF (Web Application Firewall) is blocking

================================================================================
🎓 WHAT TO LOOK FOR
================================================================================

Signs of vulnerability:
✓ Different page content between TRUE/FALSE
✓ Different response sizes
✓ Different number of results
✓ Different error messages
✓ Different loading times (for time-based blind SQLi)

Signs it's NOT vulnerable:
✗ Same response for both payloads
✗ "403 Forbidden" or "WAF blocked" messages
✗ Generic error pages
✗ Identical response sizes
